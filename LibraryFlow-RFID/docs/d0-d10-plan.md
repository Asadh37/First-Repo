# D0–D10 candidate delivery plan

| Day | Workstage | Reviewable output |
|---|---|---|
| D0 | Initiation and controls | Repository, issue tracker, assumptions, questions, risks and synthetic-data confirmation |
| D1 | Requirements | Use cases, data dictionary, RTM baseline and interface questions |
| D2 | Design | Context/component/database/security/deployment design and adapter contracts; review record |
| D3 | Foundation | Project structure, settings, DB, seed, audit, health checks and repeatable build |
| D4 | Core workflows | Catalog, member and circulation journeys |
| D5 | Search and reporting | Search, dashboard, reports and RTM update |
| D6 | RFID/interoperability | Device mocks, tag/inventory/gate/card and notification flows; retry/idempotency plan |
| D7 | Migration/resilience | 20k synthetic workbook, dry-run, reconciliation, rollback and restore rehearsal |
| D8 | Verification | Functional/integration/migration/security/performance/regression/UAT evidence register |
| D9 | Delivery | Offline package draft, admin/user/runbook documentation and demo recording |
| D10 | Review and handover | Demo, limitations, production backlog and tagged evaluation release |

This table is a planned sequence, not a claim that every stage passed formal review. Attach evidence and reviewer decisions at each gate.
